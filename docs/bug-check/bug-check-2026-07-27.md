### 修复详情
**问题 #1：map.service geocode 经纬度 0 值误判 bug**

```diff
       const location = data.geocodes[0].location;
       const [lng, lat] = location.split(',').map(Number);

-      if (!lng || !lat) {
+      // 修复原 bug：!lng || !lat 在 lng=0（本初子午线）或 lat=0（赤道）时误判为缺失
+      // 改用 Number.isFinite 显式校验 NaN/undefined，与 regeo 及 emergency.ts 路由层校验逻辑一致
+      // 设计原因：0 是合法经纬度值（赤道/本初子午线），不应被 falsy 判断误判为缺失
+      if (!Number.isFinite(lng) || !Number.isFinite(lat)) {
         return null;
       }
```

**修复原因**：
- 上一轮（commit 885623a）已修复 regeo 的同源 bug，但遗漏了 geocode
- geocode 与 regeo 处理同源数据（高德 API 返回的经纬度），校验逻辑应保持一致
- emergency.ts /map/regeo 路由层已使用 Number.isFinite，service 层应对齐

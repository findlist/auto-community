# 邻里圈自主进化 Agent 规范

> 版本：v2.0
> 更新日期：2026-07-28
> 阶段：受控建设与生产就绪核验期

## 当前原则

邻里圈仍可能存在真实业务、安全和数据一致性问题，但历史 README、开发计划与审计报告基线互相冲突。Agent 必须以当前代码、可复现测试和新审计证据为准，不得把旧报告直接当作活跃任务，也不得因 README 宣称完成而关闭问题。

成功标准是修复经过验证的问题并提高生产就绪度，不是提交数、覆盖率数字、UUID 扫描数量、样式微调或文档轮次。无合格任务时允许零修改结束。

## 有效信号

- 可复现的核心流程、安全、权限、隐私或数据一致性缺陷。
- CI、测试、类型检查、构建或迁移验证失败。
- 生产日志、监控、用户反馈和明确批准的任务。
- 对旧审计项进行当前代码复核后确认仍存在的问题。

## 基线重建

首次按 v2 运行时应进行只读生产就绪复核：

1. 将旧审计项标为“仍存在、已修复、无法确认、设计已变化”。
2. 每个“仍存在”项必须附当前文件位置或可复现测试。
3. 旧 P0 标签不自动继承优先级。
4. 基线复核本身不修改业务代码、不提交、不生成多份重复报告。

## 选择门槛

候选按 0-5 分评估：用户价值 V、严重度 S、证据 C、紧迫度 U、风险 R、成本 E。

`Score = 3V + 3S + 3C + U - 2R - E`

自动实施必须满足：`Score >= 24`、`C >= 4`、`R <= 2`，并有独立验收标准。单次最多实施最高分的 1 项。

## 权限边界

可自动实施：可复现的局部缺陷、失败测试和构建修复、明确的输入校验或越权缺陷、已授权任务的低风险步骤。

必须授权：积分和资金语义、退款和争议流程、认证与加密、多实例 Redis/WebSocket、数据库迁移、状态机、AI 决策、新依赖和跨模块架构变化。

默认拒绝：无真实缺陷支持的 UUID 扫描、常量抽取、注释补全、样式清理、覆盖率刷数和仅用于沉淀进度的文档提交。

## 运行与验证

1. 默认每天评估一次，只读取增量信号。
2. 工作区存在用户修改时必须保留，禁止顺带提交或回滚。
3. 最多列出 5 个候选并评分。
4. 无合格任务时零修改、零提交结束。
5. 实施前定义业务不变量和验收标准。
6. 对积分、状态、权限和并发修复必须补回归测试。
7. 验证失败只处理本次问题，不切换无关替代任务。

## Git 与记忆

- 达到评分门槛、`C >= 4`、`R <= 1`、工作区干净、相关前后端测试与构建全部通过，且不涉及授权范围时，必须自动按单任务 commit 并执行 `git push origin HEAD`。
- 自动推送前必须再次检查工作区与暂存文件，只能精确 `git add <本任务文件>`，禁止 `git add -A`。
- 单次最多创建并推送 1 个提交；push 失败时保留当前提交并报告，不追加提交或反复重试。
- `R = 2` 的任务不得自动提交或推送。
- 工作区启动时不干净则本轮只能评估，禁止自动提交和推送；不得回滚、覆盖或顺带提交既有修改。
- 禁止 force push、`reset --hard`、`clean -f`。
- 长期状态只保留可信基线、授权任务、仍存在的问题和用户决策；单次更新不超过 40 行。
- 已修复或过时的审计项移出活跃清单，不持续复制到 topics.md。

## 输出

```markdown
## 自主进化评估
- 新增信号：无 / 简述
- 基线变化：无 / 简述
- 最高分候选：无 / 任务名（分数）
- 决策：实施 / 提案待授权 / 零修改结束
- 验证：无 / 结果
- 用户决策：无 / 具体事项
```

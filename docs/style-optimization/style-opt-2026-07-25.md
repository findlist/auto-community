### 本次发现的可优化点

- ⚠ **Admin Dashboard 欢迎区缺少入场动画**：统计卡片已使用 `stagger-item` 错落入场（`animation-delay: idx*40ms`），但顶部欢迎区「数据统计看板」标题为静态渲染，页面加载时标题瞬现、统计卡片错落跟进，视觉节奏割裂。
- ⚠ **Admin ChartCard 缺少悬停反馈**：统计卡片已使用 `card-hover-glow`（`translateY(-2px)` + 阴影增强），但图表卡片（ChartCard 组件）仅有静态 `shadow-sm`，悬停无任何反馈，与统计卡片的交互语言不一致。07-20 报告「未优化说明」中已前瞻性指出此点。
- ⚠ **Admin Dashboard 待处理事项列表缺少错落入场**：「待处理事项」ChartCard 内的 4 个 `<li>`（待处理举报/互助总数/今日活跃/本月新增）为静态渲染，与统计卡片的 `stagger-item` 入场模式不统一。

基于以上发现，本次仅做入场动画与悬停反馈的收尾打磨，不改动任何业务逻辑、状态管理、API 调用。

## 具体修改内容

### 1. Admin Dashboard 欢迎区 —— 入场动画

**文件**：`src/pages/Admin/Dashboard.tsx`

**改动**：
为顶部欢迎区容器补 `animate-fade-in-up` 入场动画，与下方统计卡片的 `stagger-item` 错落入场形成连贯的视觉节奏。

**优化前**：
```tsx
{/* 顶部欢迎区 */}
<div className="flex items-center justify-between mb-5">
  <div>
    <h2 className="text-xl font-bold text-neutral-900 flex items-center gap-2 text-balance">
      <Activity className="w-5 h-5 text-emerald-500" />
      数据统计看板
    </h2>
    <p className="text-xs text-neutral-400 mt-1">实时反映平台运营状态</p>
  </div>
```

**优化后**：
```tsx
{/* 顶部欢迎区：fade-in-up 与下方统计卡片的 stagger-item 形成连贯入场节奏 */}
<div className="flex items-center justify-between mb-5 animate-fade-in-up">
  <div>
    <h2 className="text-xl font-bold text-neutral-900 flex items-center gap-2 text-balance">
      <Activity className="w-5 h-5 text-emerald-500" />
      数据统计看板
    </h2>
    <p className="text-xs text-neutral-400 mt-1">实时反映平台运营状态</p>
  </div>
```

**对比说明**：Dashboard 加载完成时，统计卡片通过 `stagger-item` 以 40ms 间隔错落入场，但顶部标题区为静态渲染，视觉上「标题瞬现 → 卡片错落跟进」节奏割裂。补 `animate-fade-in-up`（250ms 上浮淡入）后，标题先以柔和动画进入，统计卡片随后错落跟进，形成「标题 → 卡片 → 图表」的连贯入场层级。

### 2. ChartCard —— 悬停阴影反馈

**文件**：`src/components/Charts/index.tsx`

**改动**：
为 ChartCard 容器补 `transition-shadow duration-300 hover:shadow-md` 悬停阴影增强。刻意不使用 `card-hover-glow`（含 `translateY(-2px)` 位移），避免悬停图表数据点时卡片位移导致 tooltip 定位偏移。

**优化前**：
```tsx
export function ChartCard({ title, subtitle, children, action }: ChartCardProps) {
  return (
    <div className="bg-white rounded-2xl p-5 border border-[var(--color-border)] shadow-sm">
      <div className="flex items-start justify-between mb-4">
```

**优化后**：
```tsx
export function ChartCard({ title, subtitle, children, action }: ChartCardProps) {
  return (
    <div className="bg-white rounded-2xl p-5 border border-[var(--color-border)] shadow-sm transition-shadow duration-300 hover:shadow-md">
      <div className="flex items-start justify-between mb-4">
```

**对比说明**：Dashboard 中统计卡片使用 `card-hover-glow`（位移 + 阴影），ChartCard 仅有静态 `shadow-sm`，悬停无反馈，交互语言不一致。但图表卡片内含可交互 SVG（折线图数据点 hover 显示 tooltip、饼图扇区 hover 放大），若使用 `card-hover-glow` 的 `translateY(-2px)` 位移，悬停数据点时卡片整体上浮会导致 tooltip 位置偏移，影响读数精度。因此仅补 `hover:shadow-md` 阴影增强（`transition-shadow duration-300`），提供悬停反馈的同时不影响图表交互精度。这是 07-20 报告「未优化说明」中前瞻性提到的「进一步优化需重构 ChartCard 容器」的落地实现。

<ul className="space-y-3 text-sm">

## 未优化说明

本次审查覆盖的全部 6 个页面区域中，5 个（Home / Auth / TimeBank / SharedKitchen / SkillExchange）经评估已达到高成熟度，无需修改。具体原因见上方「审查基线评估」。以下为本次未触及但后续可考虑的点：

- **全项目 `green-*` 与 `emerald-*` 混用**：项目以 `emerald` 为品牌主色（邻里绿），但 `green-100/green-700` 作为「成功/正常/已完成」语义色广泛用于 Admin（UserManagement / ContentReview / AuditLog / ReportManagement / VerificationReview）、Emergency、TimeBank/TimeAccount、SkillExchange/Orders、SharedKitchen/Orders、Profile/PointsDetail 等约 18 处。`emerald` 与 `green` 视觉上是非常接近的绿色，混用造成细微不一致。但该模式覆盖范围广（含本次审查范围外的 Emergency / Profile），且可能是有意的「品牌色 vs 语义色」区分，建议后续单独批次评估是否统一。
- **模块色令牌与 Tailwind 工具色的细微差异**：`--color-module-timebank: #8b5cf6`（violet-500）与页面中 `bg-violet-600`（#7c3aed）存在细微色差，SkillExchange（blue-500 vs blue-600）、SharedKitchen（orange-500 vs orange-600）同理。Home 页面 ModuleRow 使用硬编码 hex 与令牌一致，模块子页面使用 Tailwind `-600` 工具色，两者在相邻元素上存在细微差异。统一需跨多文件调整，建议后续批次处理。
- **Admin 其他子页面**：本次仅优化 Dashboard。UserManagement 分页/搜索框已在 07-20 优化。其他 Admin 子页面（ContentReview / OrderManagement / ReportManagement / VerificationReview / Metrics / ABTestResults / HomepageImage / AuditLog / SystemConfig）未单独审查，但其列表页模式与 UserManagement 一致，预计无明显优化空间。
